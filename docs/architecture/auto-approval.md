# Auto Approval Reference

This document records the implemented CodexBridge work that exposes Codex
app-server automatic approval to WeChat users.

Status: implemented. Keep this file as a behavior reference, not an active
roadmap item.

## Goal

CodexBridge should let a WeChat user choose an automatic approval mode that is
semantically aligned with Codex App's auto approval behavior.

The feature must not be implemented as `approvalPolicy: "never"` or as a
shortcut for `full-access`. Automatic approval means that approval requests are
still generated when required, but app-server routes them to the native
automatic reviewer:

```ts
approvalsReviewer: "auto_review"
```

## User-Facing Command Shape

Extend the existing permission command group:

```text
/permissions auto
/perm auto
```

Expected preset meanings:

- `read-only`: manual approval, read-only sandbox
- `default`: manual approval, workspace-write sandbox
- `auto`: app-server automatic approval reviewer, workspace-write sandbox
- `full-access`: no normal approval prompts, danger-full-access sandbox

Recommended first-version reply:

```text
权限模式已切换为自动审批。
sandbox: workspace-write
approval reviewer: auto_review
```

`/permissions` and `/status` should also show the active reviewer explicitly,
for example:

```text
permissions: auto approval
sandbox: workspace-write
approval reviewer: auto_review
```

## Data Model

The bridge session settings include an approval reviewer field.

Candidate shape:

```ts
type ApprovalsReviewer = "user" | "auto_review";

interface SessionSettings {
  approvalPolicy?: string;
  sandboxMode?: string;
  approvalsReviewer?: ApprovalsReviewer;
}
```

Rules:

- `default`, `read-only`, and `full-access` should reset
  `approvalsReviewer` back to `"user"` or omit it.
- `auto` should set `approvalsReviewer: "auto_review"`.
- The field should be session-scoped like existing permission settings.
- Permission changes should keep the existing rule that they affect the next
  turn and should not mutate a currently running foreground turn.

## Provider / app-server Integration

CodexBridge passes `approvalsReviewer` through to the Codex app-server wherever
a new turn can be created or continued.

Covered call paths:

- `thread/start`
- `thread/resume`
- `turn/start`
- any goal-follow or native-goal continuation path that starts a turn
- retry / reconnect paths that rebuild turn parameters

Expected app-server parameter:

```ts
approvalsReviewer: "auto_review"
```

Compatibility requirements:

- If the current Codex CLI/app-server does not support the field, Bridge should
  fail visibly or degrade to manual approval with a clear WeChat message.
- Do not modify Codex app-server source for this feature unless upstream
  protocol support is later found to be missing. Current analysis indicates
  app-server already supports `approvalsReviewer`.

## WeChat Event Delivery

WeChat must not become silent while auto approval is happening.

Codex app-server may emit native guardian / automatic approval review events
such as:

```text
item/autoApprovalReview/started
item/autoApprovalReview/completed
guardianWarning
thread/approveGuardianDeniedAction
```

First-version WeChat behavior:

- When auto review starts, optionally show a concise notice only when it helps
  explain a delay.
- When auto review approves, avoid noisy messages unless the approval is
  important to explain subsequent behavior.
- When auto review denies, times out, or aborts, always show a visible message.
- Denial messages should include the reason or rationale if app-server provides
  one.
- If manual override is available, show the correct follow-up command.

Suggested denial message:

```text
自动审批已拒绝
原因: <rationale>
可手动处理: /allow <id>
```

If no pending manual approval id exists, do not invent one. Tell the user the
action was blocked and suggest changing permission mode or retrying with a more
specific instruction.

## Foreground / Background Interaction

Automatic approval must work consistently for both foreground and background
turns.

Requirements:

- Foreground auto approval events are delivered to the current WeChat scope.
- Background auto approval denial / timeout / abort terminal notifications are
  delivered as background task notifications.
- Background auto approval progress should remain quiet by default, consistent
  with the foreground/background design.
- `/threads allow <target>` remains the manual-control path for background
  approval requests that still require user action.
- `/stop` keeps its current foreground-only semantics.
- `/threads stop <target>` remains the background stop path.

## Status and Help

User-facing documentation and command help should continue to describe this
mode consistently:

- `README.md`
- `docs/usage/weixin-slash-commands.md`
- command help text generated by `/helps permissions`
- `/status` output examples if snapshots or docs exist

The docs must clearly state:

- `auto` is not the same as `full-access`.
- `auto` still allows app-server to deny risky actions.
- `full-access` remains the high-risk mode that suppresses normal approval
  prompts as much as possible.

## Tests

CodexBridge-only tests cover this feature. Rust app-server tests are not
required for this bridge-side behavior.

Covered test areas:

- `/permissions auto` updates session settings with
  `approvalsReviewer: "auto_review"`.
- `/permissions default`, `/permissions read-only`, and
  `/permissions full-access` clear or reset the reviewer.
- `thread/start` sends `approvalsReviewer` when the session is in auto mode.
- `thread/resume` sends `approvalsReviewer` when the session is in auto mode.
- `turn/start` sends `approvalsReviewer` when the session is in auto mode.
- goal-follow / native-goal continuation preserves the reviewer setting.
- `/status` shows auto approval mode.
- WeChat runtime surfaces auto approval denial / timeout / abort visibly.
- Background auto approval denial is delivered as a background terminal
  notification, not as ordinary foreground progress.

Targeted regression command:

```bash
node ./scripts/test.mjs test/providers/codex/app_client.test.ts test/providers/codex/plugin.test.ts test/core/bridge_coordinator.test.ts test/runtime/weixin_bridge_runtime.test.ts
```

## Acceptance Criteria

- A WeChat user can run `/permissions auto`.
- The next Codex turn uses `approvalsReviewer: "auto_review"`.
- `/permissions` and `/status` make the active mode visible.
- Automatic approval is not confused with `full-access`.
- Auto approval denials / timeouts / aborts are visible in WeChat.
- Existing manual `/allow`, `/deny`, `/threads allow <target>`, and
  foreground/background control behavior remain intact.

## Deferred Questions

- Should Bridge show every auto approval start/completion, or only denied /
  timed-out / aborted reviews? Current preference: only terminal negative
  outcomes by default, to avoid WeChat noise.
- Should `auto` use `workspace-write` only, or allow a future
  `auto-full-access` variant? Current preference: start with
  `workspace-write` only.
- Should auto approval be scope-level or session-level? Current preference:
  session-level, matching existing permission presets.
